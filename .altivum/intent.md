# Intent

## Core
An agentic loop for Claude Code that continuously refines the software it
operates in toward its author's stated intent — never adding for adding's
sake. Built for software authors: solo inventors first, teams second.

When hone is just right, its user says: my software keeps getting quietly
better without getting bigger — fidelity rises, surface area does not creep.

(Near-immutable. If this changes, hone is a different product — which is
information, not failure.)

## Boundaries
- hone is NOT a feature factory. It never proposes additions for their own
  sake: no clause, no inventor — no work. Zero gaps is a success.
- hone is NOT a market follower. External signal — trends, competitors, user
  requests — never becomes work directly; it is filed as evidence in the
  journal, and only the inventor can turn it into intent.
- hone is NOT an intent editor. It never revises an intent — not from
  findings, not from signal, not from its own judgment. Only the inventor's
  hand, deliberately.
